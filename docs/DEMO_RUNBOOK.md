# Запуск и демонстрация

## Подготовка

1. Клонировать конкурсный репозиторий либо распаковать исходники в отдельную папку. Для подтверждения истории разработки используйте Git-репозиторий или `git bundle`, а не ZIP.
2. Установить Node.js 24.x; проверить `node --version`. Двоичный runtime специально не включён.
3. Выполнить из корня `npm run verify:source`, `npm run selfcheck`, `npm test`, затем `npm start`.
4. Открыть адрес из консоли. Логины и случайные пароли взять из **собственного** `demo-data/ACCESS.txt`; не публиковать этот файл.

Нет обязательного `npm install`, базы данных или облачного ключа для стандартного локального учебного запуска. Хранилище создаётся автоматически. Локальный запуск слушает только 127.0.0.1. Для устройства на другой сети этот адрес не подходит. Опубликованная отдельная учебная веб-версия доступна по https://pactiqo.com/modus/app/; её HTTPS и права проверены отдельно, физический телефон ещё не принят.

## Сценарий 1: от сообщения до принятого улучшения

Войти как `employee` (Айдана). Создать учебное обращение о том, что для заявок на закупку не хватает модели оборудования, количества, адреса и нужной даты. Можно выбрать ручную регистрацию карточки; при доступной форме диалога сохранить сообщение и раскрыть «Проверить и зарегистрировать карточку». В автономной сборке кнопка анализа не подключает внешний ИИ.

Проверить тему, категорию, подразделение, описание и предложение; зарегистрировать. Запомнить номер и ответственного. Выйти и войти как соответствующий `owner` либо `owner2`. Начать работу, запросить пример, сохранить комментарий/план. Под автором дать уточнение. Под ответственным предъявить результат с описанием подтверждения. Под автором сначала вернуть на доработку с причиной, после исправленного результата — принять.

Проверить, что результат принят именно автором; история содержит обе редакции результата и возврат. Под `manager` показать очередь, фильтры, контроль сроков и аналитику. Даты и показатели учебного набора смоделированы и не измеряют эффект на реальных сотрудниках.

## Сценарий 2: согласование материала внутри дела

Войти как `admin`; открыть MT-0001/A-001 → «Общее обсуждение».

1. Открыть исходное PNG-изображение.
2. Открыть PDF версии 1 и вторую страницу.
3. Показать замечание автора с решением «Нужны правки».
4. Открыть версию 2; показать её отдельное согласование.
5. Объяснить следующий шаг: согласованный файл не закрывает обращение. Исполнение и приёмка результата фиксируются отдельно.
6. В новом учебном обращении добавить собственный небольшой TXT/PNG/PDF и проверить сохранение после повторного открытия комнаты.

Ограничения: до 3 файлов и до 2 МБ на сообщение, до 100 материалов в комнате. PNG/JPEG показываются как изображения, PDF — постранично, TXT — текстом, DOCX скачивается. Содержимое PDF/изображений не передаётся на OCR в этой версии; ИИ получает метаданные материалов и решений.

## Права и восстановление

Выйти и войти как `employee2`: чужое обращение недоступно. Самопроверка дополнительно проверяет HTTP-доступ и хеши всех 60 учебных файлов. Остановить процесс `Ctrl+C`, запустить снова: карточки и обсуждения должны сохраниться. Для повторения первоначального показа использовать новый пустой `--data` каталог, не стирая предыдущий.

## Частые причины отказа

| Сообщение | Действие |
|---|---|
| Node.js не найден / версия не 24 | Установить Node.js 24.x и открыть новый терминал |
| PowerShell не запускает npm.ps1 | Использовать `npm.cmd` или прямые `node scripts/...` команды |
| Порт занят | Запустить `npm start -- --port 4391` и открыть новый адрес |
| Каталог не принадлежит учебному запуску | Указать новый пустой `--data` каталог |
| Неверный пароль | Использовать пароль выбранной роли из локального ACCESS.txt данной учебной базы |
| Adapter / Codex не подключён | Это ожидаемо в автономном пакете; использовать ручную карточку и сохранённые учебные случаи |

Браузерные тесты из `source/tests` требуют отдельного Playwright и Chrome; исходные тесты поддерживают `MODUS_PLAYWRIGHT_MODULE`. Windows-установочные и реальные bridge-тесты не входят в `npm test`; они зависят от внешних компонентов полного комплекта и не должны запускаться как будто эти компоненты включены в этот пакет.
